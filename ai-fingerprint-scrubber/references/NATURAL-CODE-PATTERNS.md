# Natural Code Patterns Reference

This reference outlines idiomatic, compact coding patterns favored by experienced software engineers compared to the verbose, defensive scaffolding generated by AI assistants.

---

## 1. Guard Clauses (Early Returns) vs The Arrow Anti-Pattern

AI assistants often wrap entire functions in nested `if/else` ladders, pushing business logic 5 tabs to the right:

### ❌ AI Nested Pyramid:
```typescript
function processPayment(user: User, order: Order) {
  if (user != null) {
    if (user.isActive) {
      if (order != null) {
        if (order.total > 0) {
          return executeTransaction(user, order);
        } else {
          throw new Error("Invalid order total");
        }
      } else {
        throw new Error("Order is null");
      }
    } else {
      throw new Error("User inactive");
    }
  } else {
    throw new Error("User is null");
  }
}
```

### ✅ Clean Human Guard Clauses:
```typescript
function processPayment(user: User, order: Order) {
  if (!user?.isActive) throw new Error("Active user required");
  if (!order || order.total <= 0) throw new Error("Valid order required");

  return executeTransaction(user, order);
}
```

## 2. Variable Naming: Precision vs Hyper-Descriptive Clutter

AI models often generate absurdly long variable names that read like legal contracts:

- ❌ AI: `authenticatedUserAccountInformationPayloadResponseObject`
- ✅ Human: `user` or `userPayload`

- ❌ AI: `temporaryBooleanFlagIndicatingPaymentSuccess`
- ✅ Human: `isPaid` or `paid`

- ❌ AI: `listOfCustomerTransactionHistoryRecordItems`
- ✅ Human: `transactions`

*Rule*: Scope determines name length. A variable used in a 3-line loop should be short (`i`, `tx`, `item`, `err`). A variable with broad or global scope should be descriptive, but never verbose.

## 3. Eliminating Pointless Intermediate Variables

AI models love creating a new variable for every single step of a calculation:

### ❌ AI Intermediate Step Bloat:
```javascript
const rawTimestamp = record.created_at;
const parsedDateObject = new Date(rawTimestamp);
const formattedYearString = parsedDateObject.getFullYear().toString();
return formattedYearString;
```

### ✅ Compact Idiomatic Human Expression:
```javascript
return new Date(record.created_at).getFullYear().toString();
```

---

## 4. Avoiding Speculative Optional Chaining Everywhere

AI models often pepper code with `?.` on variables that are already strictly typed as non-null by the language or framework:

```typescript
// If 'user' is guaranteed by auth middleware:
// ❌ AI Paranoia:
const email = user?.profile?.contact?.email?.toLowerCase();

// ✅ Natural human:
const email = user.profile.email.toLowerCase();
```
Defensive programming is good at system boundaries (incoming HTTP requests, raw disk I/O, external APIs). Inside the core domain where types are known, paranoid optional chaining hides genuine structural bugs.
